# `first-principles`: 근본 사실에서 결정을 다시 세우기

정확한 실행 계약: [`skills/first-principles/SKILL.md`](../../skills/first-principles/SKILL.md)

## 한마디로

중요한 제품·기술·업무 결정에서 현재 해법과 관행을 잠시 분리하고, **관측 사실과 고정 제약에서 다시 선택지를 도출하는 읽기 전용 의사결정 스킬**입니다.

결론을 멋지게 만드는 것이 목적이 아닙니다. 증거가 충분하면 권고하고, 일부 가정이 남으면 잠정안으로 표시하며, 선택지를 구분할 수 없으면 판단 보류로 끝냅니다.

## 언제 사용하나요?

- “원래 이렇게 한다”는 관행이 현재 상황에도 필요한지 검토할 때
- 선택한 해법이 실제 문제보다 앞서 정해졌는지 확인할 때
- 중요한 제품·기술 결정의 가정을 명시적으로 반증해 보고 싶을 때
- 설계나 명세 전에 문제 framing을 다시 세울 때

이 스킬은 자동으로 실행되지 않습니다. `$first-principles`라고 이름을 직접 불러 사용합니다.

원인을 모르는 오류는 `diagnosing-bugs`, module interface나 seam은 `codebase-design`, 확인된 hotspot의 최적화는 `complexity-optimizer`가 담당합니다. `first-principles`는 코드나 문서를 수정하지 않고, 이슈·외부 시스템·Git 상태도 변경하지 않습니다.

## 무엇을 구분하나요?

- **관측 사실:** 코드, 로그, 측정, 기록이나 권위 있는 자료에서 실제로 확인한 내용
- **고정 제약:** 사용자, 저장소, 계약, 정책이나 안전 규칙이 정한 경계
- **가정:** 아직 충분히 확인되지 않았지만 반증할 수 있는 주장
- **추론:** 이름 붙인 사실과 제약에서 도출한 reasoning step
- **선호:** 사실이 아니라 특정 주체가 중요하게 여기는 판단 기준

유행, 비슷한 회사의 사례, 선례와 “best practice”는 확인할 후보일 뿐 사실의 증거로 사용하지 않습니다. 결정을 바꿀 수 있는 가정만 검사하고, 권위가 정한 제약을 단순한 가정처럼 버리지 않습니다.

## 어떤 결과를 주나요?

먼저 결정 대상, 결정 권위, 원하는 결과와 성공 기준을 정합니다. 이어서 결정에 영향을 주는 주장을 분류하고, 안전한 읽기와 계산으로 확인할 수 있는 가정을 검사합니다. 그 근거에서 현재 상태와 최소 대안을 같은 기준으로 비교합니다.

결과에는 다음 상태 중 하나가 붙습니다.

- **권고:** 현재 증거가 한 선택지를 구분하고 기존 권위 안에서 결정할 수 있음
- **잠정:** 한 선택지가 앞서지만 남은 가정이 순위를 뒤집을 수 있음
- **판단 보류:** 증거가 선택지를 구분하지 못하거나 필요한 결정 권위가 없음

각 결과에는 trade-off, 판단을 뒤집을 증거, 다시 검토할 조건과 다음 담당 workflow가 포함됩니다. 검증에 수정·외부 쓰기·production traffic이나 새 권한이 필요하면 직접 실행하지 않고 가장 작은 검증 계획에서 멈춥니다.

## 요청 예시

```text
$first-principles 마이크로서비스 전환이 정말 필요한지 관측 사실과 고정 제약부터 다시 검토해 줘.
```
